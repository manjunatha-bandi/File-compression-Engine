          How It Works: Engine Architecture
          Java 21/25 Native
        

        
Detailed breakdown of the container format, sliding window matching, and integrity guarantees.


        

          

            
1. Versioned Container Layout (CVE1)

            

              Every compressed file begins with a fixed 32-byte container header:
            

            
    
              
  • Magic (4B): 0x43564531 ("CVE1")
    • 
              
  • Version (4B): Container version (currently 1)
    • 
              
  • Original Size (8B): Uncompressed payload byte length
    • 
              
  • Block Size (4B): Size of each independent chunk (default 1 MB)
    • 
              
  • Block Count (4B): Total blocks in container
    • 
            


            
2. Block-Based Architecture & CRC32

            

              Data is segmented into independent 1 MB blocks. Each block has a 24-byte header storing the block ID, original size, compressed size, compression method ID, and an IEEE 802.3 CRC32 checksum computed over the original uncompressed block. Upon decompression, the checksum is recalculated and strictly validated.
            

          


          

            
3. Sliding Window LZ + 8-Token Flags

            

              The compressor maintains a sliding window (default 32 KB) over previously seen bytes. When a repeating sequence (min 3 bytes) is found, it encodes a 3-byte token: (distance: 2 bytes, length: 1 byte).
            

            

              Tokens are grouped in batches of 8, preceded by a 1-byte flag mask:
              bit k = 0 indicates literal character (1 byte), while bit k = 1 indicates a match token (3 bytes).
            


            
4. Automatic STORE Fallback

            

              When compressing high-entropy or pre-compressed data (e.g. encrypted files, JPEGs, ZIP archives), LZ token overhead would cause file expansion. The engine automatically detects this condition per-block: if compressedSize >= originalSize, it falls back to STORE (method 0), guaranteeing zero negative expansion.
            

          

        

      


      
      

        

          Command Line Interface (CLI) Cheatsheet
          Terminal Commands
        

        
Run the compression engine directly in your terminal using the compiled Java classes.


        

          
          

            
Start the Web Dashboard & API Server:

            

              
java -cp java/target/classes com.compression.cli.Main server 8080

              
            

          


          
          

            
Compress a file:

            

              
java -cp java/target/classes com.compression.cli.Main compress input.txt output.cve

              
            

          


          
          

            
Decompress a container:

            

              
java -cp java/target/classes com.compression.cli.Main decompress output.cve restored.txt

              
            

          


          
          

            
Inspect a container's header and blocks:

            

              
java -cp java/target/classes com.compression.cli.Main inspect output.cve
